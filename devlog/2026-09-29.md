- [x] **发现硬障碍：CORS**。在 `aipornhub.ltd` 页面的控制台用 fetch 请求 `awsprod.aiero.cc/console/api/...`，预检 `OPTIONS` 返回 **400 且无 `Access-Control-Allow-Origin`** → 浏览器拦截，四种鉴权写法（Bearer+token / token 原样 / 自定义头 / 纯 Cookie）全部失败
  - **推论（重要）**：站点自己的前端也**不可能**在浏览器里调 `console/api`（否则 CORS 必须放开）；它在浏览器里用的是 `data-public-api-prefix` 指向的 **`/api`**。也就是说 `console/api` 这套管理接口很可能是给站点运营方/创作者用的，普通用户从网页侧够不着
  - 但地址栏直接开同一地址是能通的（不经过 CORS），所以**服务器路由确实存在**，卡的是「怎么带着身份发出去」

  - 为什么带不上：站点登录态在 `aipornhub.ltd` 名下，而接口在 `awsprod.aiero.cc`，**两个域名没有共同父域（`.ltd` vs `.cc`），Cookie 不可能跨过去**；凭证只能由站点 JS 主动以标头形式附上
