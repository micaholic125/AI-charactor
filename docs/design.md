# UI 设计规范

> 界面实现必须遵循本文档。配色、组件、文案的统一标准。
> 最后更新：2026-10-26

## 1. 设计原则

- **简洁直观**：界面一屏一主题，无多余装饰；新手 10 秒内看懂
- **移动 App 风格**：底部固定导航栏，内容区可滚动
- **全中文**：所有界面文案、错误提示、确认弹窗均为中文
- **一致性**：颜色、圆角、间距只用 CSS 变量，禁止硬编码色值

## 2. 主题（theme.css，跟随系统）

字体栈：`"Segoe UI", "Microsoft YaHei", system-ui, sans-serif`
等宽字体栈（**只用于** Markdown 的代码块与行内代码）：`Consolas, "Cascadia Mono", ui-monospace, monospace`（Windows 自带 Consolas，后面几个是兜底）

```css
:root { color-scheme: light;
  --bg:#F4F5F7; --surface:#FFFFFF; --surface-2:#F7F8FA;
  --text:#1F2329; --text-2:#8A9099; --border:#E4E7EC;
  --primary:#4C6FFF; --primary-text:#FFFFFF;
  --danger:#E5484D; --ok:#16A34A;
  --bubble-user:#4C6FFF; --bubble-user-text:#FFFFFF; --bubble-ai:#FFFFFF;
  --shadow:0 1px 3px rgba(0,0,0,.06); }
@media (prefers-color-scheme: dark) { :root { color-scheme: dark;
  --bg:#141519; --surface:#1D1F24; --surface-2:#25272E;
  --text:#E7E9EC; --text-2:#8F949D; --border:#2C2F36;
  --primary:#6C87FF; --primary-text:#FFFFFF;
  --danger:#F26D72; --ok:#3DD68C;
  --bubble-user:#445EDB; --bubble-user-text:#FFFFFF; --bubble-ai:#23252B;
  --shadow:0 1px 3px rgba(0,0,0,.35); } }
```

规则：所有组件颜色一律 `var(--…)`；跟随系统由 `prefers-color-scheme` 原生实现，**不写任何 JS 主题逻辑**。

## 3. 布局规范

| 区域 | 规范 |
|---|---|
| 底部导航 TabBar | 固定底部，三栏：主页（房子图标）、我的（人像图标）、API 配置（插头/钥匙图标）；激活态主色 + 图标实心，未激活 `--text-2` |
| 主内容区 | 上方留出导航/页头，下方被 TabBar 遮挡部分用 padding 补偿；内容居中，最大宽度 ~960px |
| 卡片网格（主页） | 响应式 grid，最小卡宽 ~160px；卡片 = 头像（圆角矩形，比例 3:4 或 1:1）+ 名称 + 右上角心形收藏钮 |
| 列表（收藏/历史/对话） | 行式：头像（小圆角方形）+ 主文字 + 副文字（相对时间）+ 行尾操作按钮 |
| 聊天气泡 | 用户右对齐 `--bubble-user` 白字，**保持纯文本** `white-space: pre-wrap`；AI 左对齐 `--bubble-ai`，**按 Markdown 排版**（见 §4）；圆角 12px，最大宽度 78% |
| 空状态 | 居中图标 + 一句引导文案（如主页"还没有聊天卡，点 + 创建第一张"） |

## 4. 组件规范

| 组件 | 规范 |
|---|---|
| SearchBar | 圆角胶囊输入框 + 搜索图标；输入即过滤（名称包含，不区分大小写）；空结果显示"没有找到" |
| Avatar | 有图显示图片；无图 = 色块（8 色调色板按 card.id 哈希）+ 名字首字 |
| CardItem | 点击进入详情；心形钮点击收藏/取消（不触发跳转）；收藏态主色实心 |
| SegmentedControl | 圆角胶囊分段（我的收藏 / 游玩历史），激活段主色背景白字 |
| ConfirmDialog | 居中弹窗：标题 + 说明 + 取消/确认（危险操作确认键用 `--danger`）。**支持第二个操作键**（`altText` / `onAlt` / `altDanger`）：按钮从左到右依次是「取消」→「副操作」→「主操作」。用于「后面已有内容怎么办」这类必须二选一的场景（修改消息 / 重新输出 / 删除消息）——弹窗正文里用两行小字把两个选择的后果各说一遍，别让用户在按钮文字里猜 |
| Modal | 底部/居中弹出层：遮罩 + 面板，面板圆角 12px |
| Toast | 顶部或底部浮出，2.5 秒自动消失；成功用 `--ok`，失败用 `--danger` |
| 世界书条目行 | 标题 + 关键词 chips + 常驻徽章（"常驻"标签）+ ↑↓ 排序 + 编辑/删除 |
| 前置词 / 后置词字段（卡片编辑页） | 两个**同款的可折叠字段**，都在「角色设定」下方，都**默认折叠**（新手只看到「角色设定」一个框就够用）：<br>· **前置词（可选）**：一行可点开的标题 + 灰字「和角色设定同属人设，只是分两段写；不懂就空着」。展开后是 textarea + 灰字「这段会排在角色设定**前面**一起发送。别人写的卡常常分成前置词和正文两段，导入时会自动填上」<br>· **后置词（可选）**：标题 + 灰字「贴在 AI 回复前，管输出格式最有效；不懂就空着」。展开后是 textarea + 灰字「这段会作为消息的最后一条发送。导入别人写的卡时会自动填上」<br>折叠时若已有内容，那行灰字改成「已填写 N 字，点上面展开查看」——**不把填过的内容藏得看不出来**。**不填时都不留空消息** |
| 导入报告弹窗（导入完成后） | 标题「导入结果」。每张卡一段：**卡名**（读不出卡名就用文件名）+ 一行要点（`角色设定 1234 字 · 世界书 3 条 · 有开场白 · 有后置词`；某项没有就不显示那一项）；有警告时下面挂灰色小字**逐条**列出（被挖空的正文、忽略的字段名、头像下载失败）；失败的卡用 `--danger` 显示卡名 + 中文原因。**导入成功的卡右侧带一个「去编辑」按钮**——点了关掉弹窗、直接进这张卡的编辑页（失败的卡没有可编辑的东西，不给按钮）。底部一个「知道了」。多张卡时面板内滚动。**不合并成一句"导入完成"**——用户要知道的恰恰是每张卡各自装进来了什么。<br>标签用「**去编辑**」而不是「去补写」：导入完整的卡用户也可能想进去看看，写「补写」会让人以为出了问题；缺什么上面那行灰字已经说清了 |
| 模型选择器 ModelPicker | 下拉框；选项来自传进来的分组（一般是「当前供应商的可用模型」，按供应商地址分组显示 `<optgroup>`），下面恒有「自定义…」一项，选中后出现输入框手填列表外的模型名；传 `emptyLabel` 时多一个空选项（编辑页「用默认模型」）。**不再内置写死的模型清单**——没获取过模型列表时用一份极少量的兜底清单（deepseek-chat / deepseek-reasoner / moonshot-v1-8k / glm-4-plus / qwen-plus / gpt-4o-mini），免得下拉是空的。**卡片编辑页照旧列出全部可用模型，不跟随「常用模型」过滤**——那只收窄聊天页浮层 |
| 聊天页状态条 ChatSettingsBar | 聊天页页头下方一整条，左侧一行小字显示当前生效的 `供应商（起过名称就显示名称；没起名则显示接口地址，去掉 https:// 前缀、过长省略）· 模型名 · 流式/非流式` + 右侧下拉箭头；**最右侧另有一个独立的「调节参数」按钮**（见下一行——点它开的是参数面板，不是这个浮层）。未单独设置过时显示全局默认值。点状态条本身展开浮层，浮层内自上而下：<br>① **供应商与模型**：按供应商分组的列表——每组一行组标题（**名称；没起名则接口地址**，有名称时挂 `title` 显示完整地址 + 「使用中」徽章，点一下=只切供应商），标题下逐个模型名（点一下=切到这家并指定这个模型），当前生效的那一行打勾并高亮。<br>&nbsp;&nbsp;&nbsp;&nbsp;**列出哪些模型**：这条供应商挑过「常用模型」→ 只列挑过的这几个；一个都没挑过 → 列出全部。这家还没获取过模型列表时，组内显示一行灰字「还没获取过模型列表，去「API 配置」里点「获取模型列表」」；挑过常用模型时，在分组下方加一行灰字「这条供应商只显示你挑的常用模型（{N} 个）；想改就去「API 配置」里编辑它」。浮层里**不给**手动输入模型名的入口（手填只在「编辑供应商」里做）<br>② **取消指定**：再点一下已经打勾的那个模型即可，回到「跟着供应商的默认模型走」——浮层里**不再有**「用默认模型」「自定义模型」这类选项<br>③ **当前生效的那一行永远看得见**：只要它不在上面列出的模型里（本卡指定的模型被常用模型过滤掉了 / 早前手填的 / 旧数据；或这条供应商的默认模型不在常用模型里），就在「使用中」那组的模型列表**最前面**补一行显示它，打勾并挂小标签（本卡指定的 → 「本卡指定」；否则 → 「默认」）；点一下同样是取消指定。这样任何状态下都恰好只有一行打勾，也不会出现「有个模型在生效却看不见」<br>④ **输出方式**：两枚 chips「流式（逐字显示）/ 非流式（整段返回）」<br>⑤ 一行灰字「供应商切换影响所有卡片；模型、输出方式与生成参数只对这张卡生效」<br>点浮层外或再点状态条关闭。改动即落盘生效，无需「保存」按钮；模型多时浮层内滚动（最大高度约 60vh） |
| 卡片参数面板（聊天页「调节参数」按钮） | 状态条**右侧**一个胶囊小按钮（滑块图标 + 文字「参数」）。这张卡**单独设过**任一参数时，按钮带一个主色小圆点——不然「这张卡有没有另设过」在界面上看不出来。点开一个**独立小面板**（跟状态条浮层同一套定位与遮罩：绝对定位挂在状态条下方、点面板外关闭）：<br>· 顶部一行「这张卡的生成参数」+ 一行灰字「不设就跟着「设置」页里的全局值走」<br>· **温度**：滑条（0–2，步长 0.1，复用 `.field-range`）+ 标签里带实时数值；下方一行状态小字——本卡设过 →「本卡单独设的」；没设过 →「跟随全局（{全局值}）」。沿用设置页那句提示「角色扮演建议 0.7 ~ 1.0」<br>· **单次回复最大长度**：**数字输入框**（1–131072，复用 `.field-input`）+ 同样的状态小字。**不用滑条**——1~131072 这个跨度用滑条没法微调，跟设置页保持一致<br>· 页脚：`恢复跟随全局`（次要按钮，把这张卡的两项都清回缺省；本来就是缺省时置灰）+ `完成`（主按钮，关闭面板）<br>· 改动即落盘，**无需「保存」**；改完从下一条消息开始生效<br>· **这个面板要能长大**：参数会陆续加（Top-P / Top-K / 存在惩罚 / 频率惩罚 / 上下文长度 / 思考预算……见 requirements 3.4），所以控件**纵向排列、面板内可滚动**（最大高度约 60vh，跟状态条浮层一致），别做成只够放两个控件的固定盒子；每加一个控件只需照着现有行的样式追加<br>· **为什么单开一个门、而不是塞进状态条浮层**：参数会越来越多，一直往里塞会把浮层越拉越长，跟模型列表搅在一起；独立一个门，互不干扰 |
| 消息操作条（聊天页气泡） | 每条消息气泡**下方**的一行小按钮，**鼠标移到这条消息上才浮出**（平时 `opacity: 0` + 不接收点击，`:hover` / `:focus-within` 时淡入），这样聊天记录本身保持干净。按钮 = 图标 + 文字（非技术用户不看图标猜意思）：<br>· 用户消息：`修改` `撤回` `复制`，靠右对齐<br>· AI 消息：`创建分支` `修改` `重新输出` `删除` `复制`，靠左对齐<br>图标复用 `EditIcon` / `TrashIcon` / `RefreshIcon`，复制用新增的 `CopyIcon`。危险操作（撤回 / 删除）hover 时变 `--danger` 色。<br>**正在生成回复时整条操作条置灰**（`disabled`），`title` 提示「正在回复中，稍等一下」。<br>「重新输出」在这条消息**前面没有消息**时（对话第一条是开场白）永久置灰 |
| 消息就地编辑 | 点「修改」后，气泡本身变成 textarea（复用 `.field-textarea` 观感，宽度撑满气泡）+ 下方「保存」「取消」两个按钮。**Enter 换行、Esc 取消**——消息是多行的，Enter 不能直接保存。手感沿用对话重命名那套：先退出编辑态 → trim → 空或没改则静默返回（不提示、不落库）→ 成功后 toast，失败给中文原因。改过的消息在气泡下方挂一行灰色小字「已修改」。**编辑态显示的是原始 Markdown 文本**（`**加粗**` 原样），不是排版后的样子 |
| Markdown 排版（AI 气泡内） | 只有**已落盘的 AI 回复**排版；**用户消息与流式中的半截回复照旧纯文本**。用 `react-markdown`（+ remark-gfm + rehype-highlight）转成 React 元素，**全程不碰 innerHTML**；内容里出现的原始 HTML **不解析、按纯文字原样显示**（不执行、不加载，也不静默吞掉——AI 到底发了什么用户看得见）。<br>· 块级：段落、h1–h4 标题、有序/无序列表、引用块（左侧 3px `--border` 竖线 + `--text-2` 文字）、分隔线、表格（外面套横向滚动容器；表头 `--surface-2` 底、单元格之间 `--border` 细线）<br>· 行内：加粗、斜体、删除线、行内代码（`--surface-2` 底 + 等宽字体 + 小圆角）<br>· **链接渲染成 `<span>` 而不是 `<a>`**，只上 `--primary` 色，**点了没有任何反应**（理由见 requirements §3.4）；**图片不加载**，渲染成占位文字（如 `[图片：说明]`）<br>· 代码块：`--surface-2` 底 + `--border` 细边 + 等宽字体 + 横向滚动（长行不折行）+ 右上角「复制」小按钮（点了复制**纯代码**，走现有的 `window.api.copyText`）；带语言标记的做语法高亮，没标的灰底等宽不上色<br>· 排版容器用**独立类名**（`.bubble-text-md`），**不复用** `.bubble-text`：后者带 `white-space: pre-wrap`，而 Markdown 转出的 DOM 含大量源码换行与缩进，`pre-wrap` 会把它们变成可见空白、段落被撑开一大截。容器内首尾子元素的外边距要收掉，否则气泡上下多出空白<br>· 组件必须用 `React.memo` 包裹：流式期间每吐一个字都会重渲染整个聊天页，不 memo 的话历史气泡会被反复重新解析，长对话明显卡顿 |
| 供应商卡片（API 配置页） | 一行式：主文字 = **名称**（起过名时；接口地址以灰色小字跟在名称后面，过长省略）/ 没起名就是接口地址 +「使用中」主色徽章；副文字 = 默认模型 + 「N 个模型」（挑过常用模型时改成「常用 3 个 · 共 128 个模型」）/「未获取模型」+ Key 是否已填（「已填 Key」/「未填 Key」灰色提示）；行尾按钮：编辑 / 删除。当前使用中的那条左侧有主色竖条或主色描边 |
| 「获取模型列表」按钮（供应商表单） | 位于「模型」字段上方的一行：左侧按钮「获取模型列表」（图标 + 文字，获取中显示「获取中…」并禁用），右侧灰字显示结果（成功：「共 N 个模型 · 刚刚更新」；失败：中文说明，灰色，可重试）。失败不挡保存 |
| 常用模型挑选器（供应商表单，二级弹窗） | 表单里「可用模型」下方是「**常用模型**」字段：一行 = 按钮「挑常用模型」+ 灰字摘要（挑过：「已挑 3 个：A、B、C」，超过 5 个只列前 5 再跟「…」；没挑过：「还没挑过 —— 聊天页里会显示这家接口的全部模型；挑几个常用的，那边就只显示这几个。」）。点按钮在**当前弹窗之上再开一个弹窗**（项目里唯一一处二级弹窗）：<br>· 顶部：胶囊搜索框「搜索模型名」+ 右侧灰字「共 128 个模型 · 已选 3 个」<br>· 中间：可滚动的勾选列表（复用 `.ms-item` / `.ms-tick` 的视觉——**已勾的打勾 + 主色 + 加粗**，没勾的留出打勾位，避免文字左右跳）；列表 = 供应商的可用模型（按字母序）+ 已挑但列表里没有的名字（追加在末尾，挂灰色小字「不在列表里」）；搜索是名称包含、不区分大小写，空结果显示「没有找到匹配的模型」<br>· 下部：一行「列表里没有？[输入模型名，例如 deepseek-chat][添加]」——回车或点「添加」即选中；已在列表里的就是打勾，不在列表里的追加到末尾<br>· 页脚：`清空` `取消` `确定`（「清空」= 全部不勾，弹窗内即时生效；点「取消」**不写回**表单）<br>勾选结果**按列表顺序存**（不是点击顺序），手填的追加在末尾 |
| 选项 chips（服务商 / 接收方式） | 胶囊按钮一行排开，点一下即选中；选中项主色描边 + 主色文字（`.chip-active`） |
| 图标 | 内联 SVG 组件（icons.tsx），统一 24×24 视窗、1.5 描边；不引入图标库 |
| 聊天页「记忆」入口 | 页头右侧一个 `BookIcon` 图标按钮，`title="记忆"`；点击进入这个对话的独立记忆页。**有 `lastError` 时按钮右上角带一个 `--danger` 小圆点**（与「参数」按钮的主色小圆点同套路），不发 toast；圆点在记忆页成功整理后消失 |

## 5. 文案规范

- 语气：直接、友好、不卖萌；错误提示先给结论再给建议
- 按钮：动词短语（新建对话 / 保存 / 测试连接 / 导入）
- 确认弹窗示例：
  - 删卡片："确定删除卡片「{名称}」吗？其全部对话和头像将一并删除，不可恢复。"
  - 收藏删除："确定将「{名称}」移出收藏吗？（卡片不会被删除）"
  - 历史删除："确定将「{名称}」移出游玩历史吗？（卡片不会被删除）"
  - 对话删除："确定删除对话「{标题}」吗？其中的聊天记录将一并删除，不可恢复。"
  - 未保存退出："未保存的修改将丢失，确定退出吗？"
  - 撤回消息："确定撤回这条消息吗？它和 AI 的回复会一起删掉，文字会放回输入框。"（取消 / 撤回）
  - 修改用户消息：「修改这条消息」——"「重新回答」会让 AI 重新回复，后面的 {N} 条消息一并删掉；「只改文字」后面的消息原样保留，AI 不会重新回答。"（取消 / 只改文字 / 重新回答）
  - 重新输出：「重新输出」——"「删掉后面重来」会把这条 AI 回复和它后面的 {N} 条消息一起删掉再重新生成；「只重写这条」后面的消息原样保留。"（取消 / 只重写这条 / 删掉后面重来）
  - 删除 AI 消息：「删除这条消息」——"「只删这条」后面的消息原样保留；「这条及之后全删」会连同后面 {N} 条一起删掉。"（取消 / **这条及之后全删** / 只删这条）
- 记忆相关文案（阶段 7.0–7.5）：
  - 已覆盖消息改动：「这条消息已经写进记忆了」——"「只改原文」记忆保持不变，AI 下次可能仍按旧记忆回答；「一起整理记忆」会多调用一次 AI 修正记忆区。"（取消 / 一起整理记忆 / 只改原文）
  - 现在整理一次：「现在整理记忆？」——"这会调用一次 AI 整理记忆，可能产生费用。"（取消 / 开始整理）
  - 从头整理：「从头整理记忆？」——"会清空短期 / 长期 / 永久三层记忆，再按聊天记录重新整理；你手写的内容也会被覆盖，不可恢复。"（取消 / 从头整理）
  - 清空某一层：「清空短期记忆？」——"这一层的 {N} 条记忆会被删掉，且不会恢复；已经不再发送的旧原文也不会自动回来。"
  - 记忆页空态：短期"还没有短期记忆。聊几句后 AI 会自动记录，也可以点「添加一条」自己写。"；长期"还没有长期记忆。短期记忆满了会自动整理到这里。"；永久"还没有永久记忆。长期记忆满了会自动整理到这里。"
  - 记忆关闭：「记忆已关闭」——"这张卡关闭了记忆功能，AI 不会读写记忆；已有记忆仍然保留，重新开启后继续使用。"
  - 记忆整理失败（记忆页红色小字）："上次整理失败：{原因}（下次回复后会自动重试）"
  - 只有标记没有正文（toast）："AI 把这条回复写进了记忆"
  - 任务进行中：「正在整理记忆…」；此时编辑记忆提示「正在整理记忆，请稍候」
- 导入报告文案（阶段 6.1）：
  - 单张成功："已导入「{卡名}」：角色设定 1234 字 · 世界书 3 条 · 有开场白"
  - 多张部分成功："3 张里导入了 2 张。"（下面逐张列出，失败的那张写明原因）
  - 正文被挖空（灰色小字）："这张卡的提示词在文件里是空的（导出它的平台没有下发），导入后需要自己补"
  - 忽略字段（灰色小字）："忽略了 2 个不认识的字段：xxx、yyy"
  - 头像失败（灰色小字）："头像下载失败，已使用默认头像"
  - 世界书合并（灰色小字）："世界书是一整段文字，已作为一条常驻条目导入"

> 「这条及之后全删」虽然是破坏性更大的那个，却**不放在最右边**：右侧是手指/光标顺手就落下的位置，
> 把删得最多的选项摆在那儿容易误点。所以它作为中间那个第二操作键（红色），最右边留给「只删这条」。

以后面的条数为 0 时（是最后一条消息）：**只显示两个按钮**（取消 + 那一个动作），不摆一个没意义的二选一，正文也改成一句直说后果的话：

| 操作 | 正文 | 两个按钮 |
|---|---|---|
| 删除 | "它是最后一条消息，删掉后这一轮就没有回复了。" | 取消 / 删除 |
| 修改用户消息 | "改完让 AI 重新回答。" | 取消 / 重新回答 |
| 重新输出 | "它是最后一条消息，重新输出会把它整个换掉。" | 取消 / 重新输出 |

## 6. 错误提示文案表（详见 docs/tech.md §7）

| 场景 | 提示 |
|---|---|
| API Key 错误 | API Key 无效或未填写 |
| 权限不足 | 没有访问权限 |
| 地址/模型错误 | 接口地址或模型名称不正确 |
| 请求过频 | 请求太频繁，请稍后再试 |
| 网络不通 | 无法连接服务器，请检查网络和接口地址 |
| 图片过大 | 图片超过 5MB，请选择较小的图片 |
| 正在回复 | 正在回复中，请稍候 |
| 回复为空 | AI 没有返回内容，请稍后重试 |
| 导入失败 | 导入失败：文件格式不正确 |
| 导入的卡没带正文 | 这张卡的提示词在文件里是空的（导出它的平台没有下发），导入后需要自己补 |
| 导入时头像下载失败 | 头像下载失败，已使用默认头像 |
| 获取模型失败（网络） | 无法连接服务器，请检查网络和接口地址 |
| 获取模型失败（Key/地址） | 沿用 401/403/404 三条；404 时补一句「有些服务商不提供模型列表接口，可手动输入模型名」 |
| 获取模型成功但为空 | 这家服务商没有返回可用的模型，请手动输入模型名 |
| 换供应商后本卡模型失效 | 这张卡原先指定的是「{模型}」，新供应商里没有，已改用它的默认模型 |
| 消息不存在了 | 这条消息已经不在了，请重开对话看看 |
| 消息内容为空 | 内容不能为空 |
| 重新输出但没有上文 | 这是对话的第一条，前面没有内容可以让 AI 重新回答 |
| 分支创建失败 | 创建分支失败：{原因} |
