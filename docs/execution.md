# 执行步骤与阶段标准

> 开发流程的唯一权威标准。所有开发工作按本文档的阶段推进。
> 最后更新：2026-09-28

## 1. 开发总原则

1. **小步推进**：一次只做一个阶段的活，绝不跨阶段抢跑
2. **验证前置**：每阶段必须逐条通过「完成标准」才能进入下一阶段
3. **标准先行**：需求/技术/设计有变化，先改 docs 再改代码
4. **日志同步**：每天在 devlog 记录完成事项与待办事项（会话结束前必须更新）

## 2. 阶段划分

> **排期原则**（2026-09-29 定）：**打包发布永远排在所有功能阶段之后**——先做出能用的东西，最后再打成安装包与便携版，避免中途重打。
>
> **编号只是顺序**：6.0 / 6.1 是卡片与导入相关，7.x 留给记忆系统（待拆分），8 是打包。**新增功能阶段一律插在 8 之前。**

### 阶段 5.7：消息级操作的主进程能力 ✅
范围：`ChatMessage` 加 `id` / `editedAt`（旧数据读时补**确定性** id，不主动改写用户文件）；新 IPC `convs:update-message` / `convs:delete-message` / `convs:regenerate` / `app:copy-text`；`worldbook.ts` 的 `buildMessages` 允许省略 `currentText`；`ipc.ts` 的 `runStream` / `appendAssistant` 加 `insertAt` 参数（新回复插回原位）

完成标准：
- 老对话（消息没有 id）读出来能自动补上 id，且**主进程与渲染层算出来的是同一个**；文件不被主动改写
- 改内容：`dropAfter` 两种取值分别「只改这条」与「改完把后面的截掉」
- 删除：三种范围各删对了哪些（`'reply-too'` 只在后面确实是 AI 回复时才连删两条）
